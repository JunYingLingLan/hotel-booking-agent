# 酒店预订 Agent · 多数据源智能选房

基于开源项目 [chen2460p/hotel_booking_agent](https://github.com/chen2460p/hotel_booking_agent) 的二次开发分支。

在原版 CLI 交互原型的基础上，打通了 **Web 入口、实时房价、房型多图** 三条链路，并修复了六类影响可用性的缺陷。

> 本仓库用于个人学习与技术验证，酒店报价与图片版权归原数据提供方所有。

---

## 功能

- **多轮对话订房**：自然语言输入城市、日期、预算，逐轮补全信息后给出候选酒店与实时房型报价
- **三层数据源回退**：道旅 RollingGo MCP（真实报价）→ 高德 POI（真实名称地址）→ 内置模拟库（无网络也可演示）
- **房型实拍图**：道旅官方图 + 携程图集补充，每个房型展示 2 张
- **真实下单**：道旅 OAuth 登录后支持验价锁价、确认下单、查单、退订
- **Web 界面**：浏览器打开即用，自动选择空闲端口

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements-web.txt

# 2. 配置密钥（复制模板后填写）
cp .env.example .env

# 3. 启动 Web 版（自动选端口并打开浏览器）
python run_web.py

# 或启动 CLI 版
python main.py
```

不配置任何密钥时，程序会退化为内置模拟数据，功能仍可完整演示。

### 关于密钥

- `ROLLINGGO_API_KEY`：道旅开放平台，`mcp_` 开头，用于真实酒店搜索与房价
- `DASHSCOPE_API_KEY`：通义千问，用于自然语言理解（留空则用内置规则引擎）
- `AMAP_API_KEY`：高德开放平台，用于道旅不可用时的 POI 兜底

可用 `python setup_key.py` 交互式写入并校验。

## 架构

```
Web (FastAPI)  ──┐
                 ├─→ HotelBookingAgent（会话状态机）
CLI (main.py)  ──┘        │
                          ├─→ LLMClient（意图识别 + 参数抽取，规则引擎兜底）
                          ├─→ rollinggo_mcp（道旅 MCP 客户端）
                          ├─→ amap_poi（高德 POI 回退）
                          └─→ tools（搜索 / 报价 / 下单 / 查单）
```

图片链路：

```
前端 img → /api/img（同源代理）→ 内存缓存 → 磁盘缓存 → 道旅 CDN
                                            ↑
                        携程图集（ctrip_gallery）补充多图
```

## 相比原版的改动

### 1. 会话阶段分发下沉到 Agent

原版把 `booking` / `booking_confirm` 两个阶段的处理写在了 `main.py` 的输入循环里，导致 **Web 入口完全无法下单**。改为在 `HotelBookingAgent.run()` 开头统一分发，CLI 与 Web 共用同一套流程。

### 2. 中文口语解析

- 支持「两百元」「一千五」「三百五左右」等中文金额 → 预算
- 支持「明天入住后天离店」「大后天」等相对日期，并按「入住 / 离店」语境分别落位
- 「住两晚」等中文数字晚数

### 3. 出列表后的条件筛选

原版在推荐列表后收到「两百元一晚」会回复「请输入 1-N 之间的序号」（因为文本里含数字）。改为：

- 若本轮解析出预订参数 → 按新条件**重新搜索**
- 只有纯数字或「第 N 家」才当作选店

### 4. 房型列表交互

新增「更多房型 / 全部房型 / 展开房型」指令，展开被截断的房型列表（默认展示前 8 档）。

### 5. 图片链路（问题最多的一块）

| 问题 | 根因 | 解法 |
|---|---|---|
| 图片全部显示为链接 | 跨源 `<img>` 被 ORB 拦截（CDN 返回 XML 时） | 同源代理 `/api/img` + 白名单防 SSRF |
| 代理后仍大量失败 | 请求带了 `Referer`，道旅 `room-type` 桶**不允许任何 Referer** | 代理**不带 Referer**，两种桶都能过 |
| 间歇性失败 | CDN 偶发抖动（非限流，重试即成功） | 前端 4 轮重试 + 服务端重试 + 占位图降级 |
| 点开链接看到 JSON 报错 | 抓取失败时直接 `raise HTTPException` | 返回内联 SVG 占位图，永不暴露异常 |
| 每个房型只有 1 张图 | 道旅 `roomInfo.images` 只有单个 URL | 携程图集补充（见下） |
| 房型图偶发 404 | 该房型在 CDN 上确实不存在 | 标记 `_IMG_GONE`，不再重试 |

### 6. 携程房型图集（`ctrip_gallery.py`）

道旅每个房型只给一张图，而携程详情页内嵌的 `subImgUrlList` 里 `imgTitle` 就是房型名，每房型 1~9 张图。

链路：

```
酒店名 → 360/百度搜索「酒店名 携程」→ 携程 hotelId
      → 详情页解析 subImgUrlList → 按 imgTitle 分组
      → 与道旅房型名四层模糊匹配 → 每房型取 2 张
```

两个关键坑：

1. 携程站内搜索不响应关键词、浏览器访问会跳登录页、索引页是 SPA 空壳 —— 只能靠搜索引擎索引定位 ID
2. Python `requests` 的 TLS 指纹会被搜索引擎识别（返回 1.4 KB 精简页），必须用 Node 子进程发请求

结果带 7 天磁盘缓存；任何异常静默返回空，**绝不阻塞订房主流程**。价格始终来自道旅，不使用携程的价格数据。

## 目录说明

| 文件 | 作用 |
|---|---|
| `agent.py` | 会话状态机，意图路由与流程编排 |
| `llm.py` | 意图识别与参数抽取（规则引擎 + 可选大模型） |
| `rollinggo_mcp.py` | 道旅 MCP 客户端、搜索与详情富化 |
| `rollinggo_book.py` | OAuth 登录、验价锁价、下单、退单 |
| `ctrip_gallery.py` | 携程房型图集补充（新增） |
| `ctrip_crawler.py` | 携程图集抓取（原版遗留，已被上者取代） |
| `web.py` | FastAPI 服务与图片代理 |
| `run_web.py` | 自动选端口并打开浏览器的启动器（新增） |
| `setup_key.py` | 交互式密钥配置与校验（新增） |
| `tools/find_ctrip_id.mjs` | 用搜索引擎定位携程 hotelId（新增） |

## 已知限制

- 携程图集依赖搜索引擎索引，部分酒店（尤其新房型、英文房型名）匹配不到，会退回道旅单图
- 道旅 CDN 的图片请求偶发失败，靠重试兜底，个别图片仍可能降级为占位图
- 评分模块依赖未配置的第三方接口，界面显示「暂无评分」
- 订单默认存内存，重启丢失；可解注释 `.env` 里的 `DATABASE_URL` 启用 SQLite
